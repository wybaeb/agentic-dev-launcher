0Что получится

Два контейнера: router — LiteLLM с гардрейлом секретов, wrangler — погонщик с параллельными субагентами. Учебный проект — сервис международных переводов, красная приёмка до работы агентов. Время на всё: 20–30 минут, из них 10 — сборка образа.

человек ──▶ wrangler (planner) ──┬─▶ worker T1  ветка task/T1 ─┐
                                 ├─▶ worker T2  ветка task/T2 ─┼─▶ merge → integration → reviewer
                                 └─▶ worker T3  ветка task/T3 ─┘
                 все запросы ──▶ router ──▶ secret_shield ──▶ OpenRouter

3Ключи и .env

Ключ — в кабинете OpenRouter. Модели — любые id OpenRouter без префикса openrouter/.

Корпоративный шлюз, совместимый с OpenAI API. Роутер стенда встанет перед ним: гардрейл и журнал остаются нашими.

Ollama на хосте. Нужна модель с вызовом инструментов (например, qwen2.5-coder:32b); медленнее, но без ключей.

Положите файл как stand/.env. Он не коммитится; роутер маскирует всё, что в нём лежит.

Мастер-ключ подставляется во все команды ниже. Если в запросе к роутеру ключ не совпадает с LITELLM_MASTER_KEY из .env, LiteLLM отвечает не «401», а No connected db — он идёт искать ключ в базе, которой у стенда нет. Это всегда означает «не тот ключ».

Роутер → корпоративный шлюз

В router/litellm_config.yaml замените openrouter/${…} на openai/<модель> и добавьте api_base: os.environ/LLM_GATEWAY_URL, ключ — os.environ/LLM_API_KEY.

Роутер → Ollama

# router/litellm_config.yaml, вместо openrouter/…:
#   model: ollama_chat/qwen2.5-coder:32b
#   api_base: http://host.docker.internal:11434

5Подключите движок субагентов встроенный

Ничего настраивать не нужно: собственный цикл инструментов внутри контейнера ходит в роутер. Гард харнесса стоит на каждом вызове инструмента.

Codex уже в образе; конфиг /root/.codex/config.toml смотрит на роутер через протокол Responses, ключ — LITELLM_MASTER_KEY. Проверка:

docker compose exec wrangler codex --version
docker compose exec -w /workspace/korona-transfers wrangler codex exec --sandbox danger-full-access --skip-git-repo-check -m worker "Назови файлы в app/ одной строкой"

В контейнере: opencode.json лежит в корне учебного проекта и указывает на роутер. На хосте — тот же конфиг с адресом 127.0.0.1:4000:

# в контейнере
docker compose exec -w /workspace/korona-transfers wrangler opencode run --model litellm/worker "Назови файлы в app/ одной строкой"
# на хосте: веб-интерфейс к агенту поверх роутера стенда
cp opencode.host.json workspace/korona-transfers/opencode.json
export LITELLM_MASTER_KEY=…
cd workspace/korona-transfers && opencode web --port 4096   # откроется http://127.0.0.1:4096

OpenCode напрямую к OpenRouter — тоже можно (opencode → /connect → OpenRouter), но тогда гардрейл роутера стенда остаётся в стороне: для демонстрации секретов ходите через роутер.

Claude Code снаружи контейнера, для отладки: погонщик запускается на хосте и вызывает claude -p; субагенты — тоже Claude Code. Через роутер стенда этот путь не идёт.

python3 -m venv .venv && . .venv/bin/activate && pip install openai pytest httpx fastapi
PYTHONPATH=wrangler LOGS=logs python3 -m wrangler workspace/korona-transfers --engine claude --parallel 2

Показываем: в ответе и в журнале — ▒▒▒▒▒[secret:ROUTER_PASSWORD]. Модель значение не получила. Текстовый запрет в промпте так не работает — это ограничение среды.

7.3 · Большая задача запуск на 40-й минуте, идёт фоном

Сначала короткая разминка — две подзадачи параллельно, 5–8 минут; на занятии её можно пропустить, если прогнали на проверке:

> task Реализуй модули app/ledger.py и app/fx.py строго по spec/CONTRACTS.md, каждый со своими модульными тестами в tests/unit/. HTTP-слой не трогать. Это две независимые подзадачи — делай их параллельно.
> plan
> go

Большая задача целиком:

> task Собери сервис переводов по spec/TASK.md: пять модулей app/ledger.py, app/fx.py, app/fees.py, app/transfers.py, app/notify.py и HTTP-слой app/main.py по spec/CONTRACTS.md, с модульными тестами на каждый модуль, до зелёной приёмки tests/acceptance. Модули независимы и делаются параллельно; transfers и HTTP — после них.
> plan
> go
Говорим: «План — граф зависимостей: четыре модуля параллельно, transfers после них, HTTP последним. Каждому — своя ветка. Пока они работают, я с погонщиком на связи». Возвращаемся к слайдам.

4Промпт для первого прогона

Прочитай AGENTS.md и следуй ему. Задача TASK-001: спецификация в spec/TASK-001.md.
Сначала предъяви план по шагам и остановись — жди подтверждения.
После подтверждения: тесты на критерии приёмки, затем реализация, затем python3 -m pytest -q.
Границы изменений — из спецификации. Готово, когда все тесты зелёные и есть отчёт: что сделано, что проверено, что осталось.
